# Штаб Офлайн — тестовая синхронизация 0.2-pre

## Что создано

- Независимая **тестовая** Google Sheets с 5 вымышленными делами, 3 заседаниями и отдельным журналом операций `Ops`:
  https://docs.google.com/spreadsheets/d/1BW68gb2l5HxcHZ0Fn-BAM91XZCPyQ-QOijRaCibQ9as/edit
- Полный серверный файл `server/ТестСинхронизация.gs` — новый изолированный Apps Script, **не в рабочей CRM**.
- Отдельная тестовая PWA по адресу `https://goeg89.github.io/shtab-offline-demo/sync-test/` после публикации файлов в GitHub Pages.
- Прежний стабильный адрес `https://goeg89.github.io/shtab-offline-demo/` остаётся без изменений.

## Установка изолированного сервера

1. Открой **только тестовую** таблицу по ссылке выше.
2. Выбери `Расширения → Apps Script`. Откроется отдельный проект скрипта именно этой тестовой таблицы.
3. Открой существующий файл `Код.gs` (или `Code.gs`) и **полностью замени его содержимое** текстом файла `ТестСинхронизация.gs` из ZIP. Имя вкладки скрипта можно оставить `Код.gs`, если это единственный серверный файл. Не вставляй этот код в рабочий проект «Мои дела».
4. Сохрани. В выпадающем списке функций выбери `setupTestSync` и нажми **Выполнить**, пройди авторизацию доступа к **тестовой таблице**. В журнале выполнения появится строка `SECRET — ВВЕДИТЕ...` с **64-символьным ключом**.
5. **Не присылай ключ в ChatGPT и не записывай его в GitHub.** Введёшь его только в поле тестового PWA на iPhone.
6. Нажми `Развернуть → Новое развёртывание → Веб-приложение`. Выбери: `Выполнять от имени: меня`; `Доступ: все (Anyone)` — **только потому, что в этом тестовом проекте нет ни одного реального клиента**. Нажми `Развернуть`, скопируй ссылку вида `https://script.google.com/macros/s/AKfy.../exec`.
7. Открой тестовую PWA `https://goeg89.github.io/shtab-offline-demo/sync-test/` в Safari. Во вкладке **Очередь изменений** вставь URL `/exec` и секрет из своего журнала, нажми **Подключить тестовую базу**. Должно загрузиться 5 дел и 3 события.

## Проверка офлайн → онлайн

1. С интернетом и пустой очередью открой тестовое дело Иванова.
2. Переведи iPhone в авиарежим, дополнительно выключи Wi-Fi, измени тестовую задачу и сохрани. Счётчик очереди должен показать 1.
3. Полностью закрой приложение и открой снова. Убедись, что задача и счётчик сохранились.
4. Включи интернет. Если приложение не отправило очередь само, на вкладке **Очередь изменений** нажми **Отправить очередь**.
5. Убедись, что очередь стала 0 и сообщение сообщает о подтверждённой записи.
6. Открой **тестовую** Google Sheets. На листе `Cases` найди CASE-DEMO-001: новая задача должна быть в `C`, ревизия `H` увеличиться; на листе `Ops` должен появиться один `OP-...` со статусом `applied`.
7. Если написано «нет подтверждения», **не удаляй очередь**. Проверь тестовый лист `Ops` и повтори отправку с тем же ID: сервер не должен создавать дубль.

## Ограничения и безопасность

- **Это не защищённая продуктивная интеграция и не рабочая CRM.** Режим `Anyone + секрет в localStorage` годится только для фиктивных демоданных. URL публичного GitHub Pages не предоставляет индивидуальную авторизацию.
- Сервер жёстко привязан только к тестовому Spreadsheet ID; принимает лишь `CASE-DEMO-...` и ограниченные изменения задач, сроков и тестовых заседаний.
- Клиент подписывает обращения HMAC; сервер ведёт журнал операций и проверяет ревизии. Однако реальный сетевой транспорт между GitHub Pages и Apps Script на iPhone требует ручного тестирования: GET через JSONP, POST через скрытую HTML-форму, подтверждение через GET. Ошибка CORS или ограничения Safari могут заблокировать передачу.
- При конфликте локальная правка остаётся в очереди; автоматического объединения и интерфейса разрешения конфликтов пока нет.
- Не использовать для настоящих клиентов, документов, актов, XP, доверенностей и персональных данных. Для настоящей CRM потребуется отдельная аутентификация (OAuth/сессия), закрытый серверный шлюз и расширенная проверка безопасности.
- Полные `Штаб.html`, `ШтабКод.gs` и мобильный `/exec` **не менялись**. Рабочие данные также не затронуты.

После замены и сохранения `Код.gs` и публикации его **отдельного тестового Web App** напиши: **готово**. Это подтверждает установку, но не прохождение теста; результат теста спросим отдельно.
